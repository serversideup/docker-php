::lead-p
Every tag answers three questions: which PHP, which web server, and which operating system. `serversideup/php:8.5-fpm-nginx` is PHP 8.5 with NGINX on Debian. Answer the three below, and you have your tag.
::

## Pick the variation that matches how you serve PHP

| If you want | Use | Learn more |
|---|---|---|
| NGINX and PHP-FPM in one container. A common choice for Laravel. | `fpm-nginx` | [fpm-nginx](/docs/image-variations/fpm-nginx) |
| One process serving PHP through Caddy, with worker mode, HTTP/2, and HTTP/3. | `frankenphp` | [frankenphp](/docs/image-variations/frankenphp) |
| Apache with `.htaccess` support in front of PHP-FPM, such as for WordPress. | `fpm-apache` | [fpm-apache](/docs/image-variations/fpm-apache) |
| PHP-FPM on port `9000`, behind a web server or load balancer you run yourself. | `fpm` | [fpm](/docs/image-variations/fpm) |
| PHP without a server, for scripts, Composer, queue workers, and CI. | `cli` | [cli](/docs/image-variations/cli) |

A tag that names no variation gets `cli`. Every variation runs as `www-data` and takes its settings from environment variables.

::note
The `unit` variation was removed in v4.1.0 (November 21, 2025) after NGINX archived NGINX Unit. See [Unit](/docs/image-variations/unit) to move off it.
::

## Use the newest PHP your app supports

Pick the newest PHP version your dependencies support that php.net still [supports](https://www.php.net/supported-versions.php){target="_blank"}. The [PHP changelog](https://www.php.net/ChangeLog-8.php){target="_blank"} lists what changed in each release.

New PHP patches don't wait on us. We check php.net every hour, and a new patch starts a build right away. The images publish once that build passes its tests. `8.6-rc` tracks the newest PHP 8.6 release candidate, such as `serversideup/php:8.6-rc-fpm-nginx`. Use it for testing, not production.

PHP 8.1 is end of life upstream. We still build it for operating system fixes, but PHP itself gets none. PHP 7.4 and 8.0 are no longer built at all. Their tags still pull, frozen with no updates. See [EOL versions and the legacy-modernization path](https://github.com/serversideup/docker-php/blob/main/SECURITY.md#eol-versions-and-the-legacy-modernization-path).

## Pick Debian or Alpine

Both get the same PHP, the same defaults, and the same release schedule. Choose the one that fits your app.

| | Debian | Alpine |
|---|---|---|
| Download size of `8.5-fpm-nginx` | ![8.5-fpm-nginx image size](https://img.shields.io/docker/image-size/serversideup/php/8.5-fpm-nginx?label=size) | ![8.5-fpm-nginx-alpine image size](https://img.shields.io/docker/image-size/serversideup/php/8.5-fpm-nginx-alpine?label=size) |
| C library | glibc | musl |
| Variations | All five | All but `fpm-apache` |
| Tags | `-debian` (Trixie), `-trixie`, `-bookworm` | `-alpine` (newest), `-alpine3.22`, `-alpine3.23`, `-alpine3.24` |

**Alpine** images are much smaller. They pull faster, start new servers sooner, and take less disk on every host. Alpine also ships fewer packages, which leaves less for a vulnerability scanner to flag.

**Debian** uses glibc, which most prebuilt binaries and PHP extensions expect. Something that works on your laptop or in a typical CI runner is more likely to work unchanged. That's why a tag with no OS gets Debian Trixie.

Before you pick Alpine, check that every extension and package your app needs builds against musl. FrankenPHP has [known performance issues](https://frankenphp.dev/docs/known-issues/){target="_blank"} on Alpine upstream. `-alpine` gets the newest Alpine for that PHP version: Alpine 3.24, or Alpine 3.22 for PHP 8.1.

Whichever you choose, stay on a release that still gets security updates. When a release reaches end of life, we stop building it and its tags freeze, as Debian Bullseye and Alpine 3.16 did. Check the [Debian](https://endoflife.date/debian){target="_blank"} and [Alpine](https://endoflife.date/alpine-linux){target="_blank"} lifecycles.

|---|---|---|---|---|---|
| `cli`, `fpm`, `fpm-nginx` | 8.1 to 8.6-rc | 8.1 to 8.6-rc | 8.1 | 8.2 to 8.6-rc | 8.2 to 8.6-rc |
| `fpm-apache` | 8.1 to 8.6-rc | 8.1 to 8.6-rc | ❌ | ❌ | ❌ |
| `frankenphp` | 8.3 to 8.6-rc | 8.3 to 8.6-rc | ❌ | 8.3 to 8.6-rc | 8.3 to 8.6-rc |

## Every tag reads the same way

```txt
{{registry}}/serversideup/php:{{prefix}}-{{php-version}}-{{variation}}-{{os}}-{{release}}
```

Every part is optional except the repository.

| Part | Default | Other values |
|---|---|---|
| `{{registry}}` | Docker Hub | `ghcr.io` for GitHub Packages |
| `{{prefix}}` | none (stable) | `beta` |
| `{{php-version}}` | newest stable minor | `8.4`, `8.1`, `8.6-rc`, a major such as `8`, or a patch such as `8.4.27` |
| `{{variation}}` | `cli` | `fpm`, `fpm-nginx`, `fpm-apache`, `frankenphp` |
| `{{os}}` | `debian` (Trixie) | `bookworm`, `trixie`, `alpine`, `alpine3.22`, `alpine3.23`, `alpine3.24` |
| `{{release}}` | none (floating tag) | a [GitHub release](https://github.com/serversideup/docker-php/releases){target="_blank"} such as `v5.0.5` |

## Floating tags stay patched, pinned tags never change

A tag without a release, such as `8.5-fpm-nginx`, floats. We rebuild it with every PHP patch and each week with operating system security fixes.

A tag with a release, such as `8.5-fpm-nginx-v5.0.5`, is pinned. It never changes. The [upgrade guide](/docs/upgrading/upgrade-guide) explains when to use each.
