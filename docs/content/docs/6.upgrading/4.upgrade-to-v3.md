::lead-p
Version 3 rebuilt the images on the official PHP images and runs them as an unprivileged user. Most v2 setups need changes to ports, file ownership, and how extensions are installed.
::

## Stay on v2 while you migrate

Add `-v2.2.1` to your tag so you aren't upgraded before you're ready:

```yaml [compose.yml] {3}
services:
  php:
    image: serversideup/php:8.2-fpm-nginx-v2.2.1
```

## Breaking changes

| Change | Likelihood of impact | You're affected if |
|---|---|---|
| [Web servers listen on 8080 and 8443](#web-servers-listen-on-8080-and-8443) | High | You use `fpm-nginx` or `fpm-apache` |
| [Files belong to `www-data`, not `webuser`](#files-belong-to-www-data-not-webuser) | High | You mount volumes or `COPY` files into the image |
| [Debian and Alpine replace Ubuntu](#debian-and-alpine-replace-ubuntu) | High | Your Dockerfile runs Ubuntu commands or uses `ppa:ondrej/php` |
| [Renamed and removed variables](#renamed-and-removed-variables) | Medium | You set any of the variables listed |
| [`AUTORUN_ENABLED` defaults to `false`](#autorun_enabled-defaults-to-false) | Medium | You rely on the Laravel automations |
| [`SSL_MODE` defaults to `off`](#ssl_mode-defaults-to-off) | Medium | You relied on HTTPS by default |
| [S6 Overlay only in `fpm-nginx` and `fpm-apache`](#s6-overlay-only-in-fpm-nginx-and-fpm-apache) | Low | You added S6 services to `cli` or `fpm` |
| [MSMTP is removed](#msmtp-is-removed) | Low | Your app sends mail through MSMTP |

### Web servers listen on 8080 and 8443

Unprivileged users can't bind ports below 1024. NGINX and Apache now listen on `8080` for HTTP and `8443` for HTTPS. Update your port mappings, for example `80:8080` and `443:8443`. See [Default configurations](/docs/getting-started/default-configurations).

### Files belong to `www-data`, not `webuser`

Version 2 ran as `webuser` (UID `9999`) with a login shell. Version 3 uses the `www-data` user that ships with the official PHP images: UID and GID `33` on Debian and `82` on Alpine.

- `chown` mounted volumes on your hosts to match, for example `33:33`.
- Copy files with the right owner: `COPY --chown=www-data:www-data . /var/www/html`.
- To match your own UID in development, see [Understanding file permissions](/docs/customizing-the-image/understanding-file-permissions). For Docker Swarm host volumes, the [change-volume-permissions script](https://github.com/serversideup/docker-volume-change-permission-script){target="_blank"} can help.

### Debian and Alpine replace Ubuntu

The images build on the official PHP images, which use Debian or Alpine. PHP comes from php.net instead of `ppa:ondrej/php`. Remove Ubuntu-specific commands from your Dockerfile. Replace packages like `php-redis` with `install-php-extensions`. See [Installing additional PHP extensions](/docs/customizing-the-image/installing-additional-php-extensions).

### Renamed and removed variables

| v2 | v3 |
|---|---|
| `WEBUSER_HOME` | `APP_BASE_DIR` |
| `DEBUG_OUTPUT` | `LOG_OUTPUT_LEVEL=debug` |
| `PHP_POOL_NAME` | `PHP_FPM_POOL_NAME` |
| `PHP_PM_CONTROL`, `PHP_PM_MAX_CHILDREN`, `PHP_PM_START_SERVERS`, `PHP_PM_MIN_SPARE_SERVERS`, `PHP_PM_MAX_SPARE_SERVERS` | `PHP_FPM_PM_CONTROL`, `PHP_FPM_PM_MAX_CHILDREN`, `PHP_FPM_PM_START_SERVERS`, `PHP_FPM_PM_MIN_SPARE_SERVERS`, `PHP_FPM_PM_MAX_SPARE_SERVERS`. The old names are ignored, so your PHP-FPM tuning is lost until you rename them. |
| `PUID`, `PGID` | Removed, because changing IDs at runtime needs root. See [Understanding file permissions](/docs/customizing-the-image/understanding-file-permissions). |
| `MSMTP_RELAY_SERVER_HOSTNAME`, `MSMTP_RELAY_SERVER_PORT` | Removed with MSMTP |

Check every variable you set against the [environment variable reference](/docs/reference/environment-variable-specification).

### `AUTORUN_ENABLED` defaults to `false`

The Laravel automations no longer run unless you set `AUTORUN_ENABLED=true`. See [Laravel automations](/docs/framework-guides/laravel/automations).

### `SSL_MODE` defaults to `off`

The images serve HTTP only by default. Set `SSL_MODE` to turn HTTPS on. See [Configuring SSL](/docs/deployment-and-production/configuring-ssl).

### S6 Overlay only in `fpm-nginx` and `fpm-apache`

The other variations don't include S6 Overlay. Move start-up scripts for them to `/etc/entrypoint.d`. See [Adding your own start-up scripts](/docs/customizing-the-image/adding-your-own-start-up-scripts).

### MSMTP is removed

MSMTP was removed for security and image size. Send mail through an external SMTP service. If you need MSMTP, install it in your own Dockerfile.

## New features

- Built on the official PHP Docker images.
- Runs as an unprivileged user by default.
- Tags for an exact PHP patch, such as `8.2.12` instead of `8.2`.
- Start-up scripts in `/etc/entrypoint.d`, with no S6 Overlay knowledge needed.
- Laravel automations for `config:cache`, `route:cache`, `view:cache`, `event:cache`, `migrate --force --isolated`, and `storage:link`.
- Images published to GitHub Packages as well as Docker Hub.

## If your CI runs builds as root

Build a separate CI target that stays as `root`. Keep `www-data` for the image you deploy. When the container runs as root, the image sets PHP-FPM's worker user to `www-data` for you (`PHP_FPM_CHILD_PROCESS_USER`). Start from the multi-stage Dockerfile in [Understanding file permissions](/docs/customizing-the-image/understanding-file-permissions) and add a `ci` target that sets `USER root`.

## Migration checklist

1. Test in a non-production environment first.
2. Update the image tag and the port mappings to `8080` and `8443`.
3. Check every environment variable you set.
4. In your Dockerfile, remove Ubuntu commands and `ppa:ondrej/php`, install extensions with `install-php-extensions`, and `COPY` with `--chown=www-data:www-data`.
5. `chown` host volumes to `33:33` (Debian) or `82:82` (Alpine).
6. Add `PHP_OPCACHE_ENABLE=1` in production.
7. Deploy.
